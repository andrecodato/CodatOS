# Medição em repouso — M0

> **Status**: Medido em 2026-10-17 · janela fechada: **30,4 MB** working set, **5,4 MB** private, **0%** CPU — atende ao RNF-DES-01.

O M0 só fecha com a "RAM em repouso medida" ([roadmap](../09-roadmap.md#m0--fundação)). Este documento registra o método e os números.

## Alvo

| ID | Critério | Origem |
|---|---|---|
| RNF-DES-01 | Em repouso (janela fechada, na bandeja): **CPU média < 1%** e **RAM < 80 MB** (núcleo, sem WebView). Com janela aberta: RAM < 300 MB. | [Requisitos](../01-requisitos.md) |
| — | **Dado** que a janela foi fechada, **quando** se passam 30 s, **então** a RAM do app fica abaixo de 80 MB. | [App e configurações → critérios de aceite](../modulos/app-e-configuracoes.md#critérios-de-aceite) |

No M0 o RNF-DES-01 é **medido**, não cobrado: a meta passa a ser obrigatória na saída do M1. Mesmo assim, o número do M0 é a linha de base para ver se o núcleo cresce a cada marco.

## Método

O script [`scripts/measure-idle.ps1`](../../scripts/measure-idle.ps1):

1. Abre o `codatos.exe` e espera a janela principal aparecer (até 30 s).
2. Fecha a janela com `CloseMainWindow()` (o mesmo `WM_CLOSE` do botão X). No M0 isso destrói a WebView e o app fica na bandeja.
   - Com `-Autostart`, em vez disso, inicia com `--autostart` (já na bandeja, sem janela).
3. Espera `-WaitSeconds` (padrão **30 s**).
4. Amostra a CPU da árvore por `-CpuSampleSeconds` (padrão **10 s**): soma do tempo de CPU ÷ (tempo decorrido × núcleos lógicos).
5. Coleta o processo `codatos` e **todos os descendentes**, percorrendo `ParentProcessId` no `Win32_Process` — é assim que entram os `msedgewebview2` que ainda estiverem vivos.
6. Soma **working set** (`WorkingSet64`) e **private bytes** (`PrivateMemorySize64`) e imprime por processo e no total, em MB.
7. Encerra o app (sempre, mesmo se algo falhar).

Também registra SO, CPU, RAM total, versão do WebView2 Runtime (`pv` em `HKLM\SOFTWARE\WOW6432Node\Microsoft\EdgeUpdate\Clients\{F3017226-FE2A-4295-8BDF-00C3A9A7E4C5}`) e a versão do app (versão do arquivo).

**Qual número vale**: para o RNF-DES-01 usamos o **maior** entre working set e private bytes totais. Working set é o que o Gerenciador de Tarefas mostra como "Memória"; private bytes é o que o processo realmente alocou e não divide com ninguém.

**Regras para medir**:

- Use o build de release (`just build-win` ou o instalador NSIS), nunca o `cargo tauri dev`.
- Nenhuma outra instância do CodatOS aberta (o script recusa se houver uma).
- Rode 3 vezes e registre a **mediana**.

## Como rodar

No Windows (PowerShell 7 ou Windows PowerShell 5.1), na raiz do repositório:

```powershell
# Binário de `just build-win` (padrão)
powershell -ExecutionPolicy Bypass -File scripts\measure-idle.ps1

# App instalado pelo NSIS (instalação por usuário; confira o caminho),
# iniciando já na bandeja, saída em JSON
powershell -ExecutionPolicy Bypass -File scripts\measure-idle.ps1 `
  -ExePath "$env:LOCALAPPDATA\CodatOS\CodatOS.exe" -Autostart -Json
```

Do WSL, depois de `just build-win`:

```bash
just measure-idle            # mesmos parâmetros do script, ex.: just measure-idle -Json
```

| Parâmetro | Padrão | O que faz |
|---|---|---|
| `-ExePath` | `target\x86_64-pc-windows-msvc\release\codatos.exe` | Caminho do executável |
| `-WaitSeconds` | `30` | Espera depois de fechar a janela |
| `-CpuSampleSeconds` | `10` | Janela de amostragem da CPU (`0` desliga) |
| `-Autostart` | — | Inicia com `--autostart` em vez de abrir e fechar a janela |
| `-Json` | — | Saída em JSON |
